# 車身脫困候選修正（2026-09-12）

## 範圍與裁決

使用者同意先改善車身安全脫困動作選擇，再實跑判定是否需要砲塔控制。沿用既有 Windows 單人訓練場、產品優先、NavMesh＋載具駕駛的定位與動機；不新增目標使用者或通用規劃器。這是已實作系統的局部 bug 修正，不重新設計索敵架構。

證據：`/tmp/trace-pose-probe-report.md` 重建 f4604、f4906 原姿態，原命令皆被 gun/#14 拒絕；同姿態另有非零車身候選安全。候選安全不等於真實持續脫困成功，因此須實際物理驗證。

## 最小方案

1. 新增 `Predictor.choose_recovery(movement, turn, goal, delta)`，一般 `choose` 行為不變。共用一次 snapshot、起始接觸、時間與查詢預算、完整 probe 和 trace，不逐候選重啟 choose。
2. 原命令安全即保留，包含能安全分離既有接觸的情況。原命令 0/0 僅驗證原命令；煞車及各停穩階段不得自行開始移動。
3. 原動作不安全才列有限候選：非零 movement 用同符號 `min(abs(movement), 0.1)`，搭配低幅原轉向、0、左右 0.2，再原地左右 0.2；純轉向用同向低幅與反向低幅。去重、clamp，含 nominal 不超過既有 12 個上限。
4. 固定順序選第一個安全非零候選，不使用接近路線目標的分數壓掉必要倒車。不鎖死原轉向側；沒有安全候選或耗盡預算即輸出停止。
5. Navigation 的 recovery 出口接入新入口。Recovery 的階段、時間、最多兩次重試及目標改變後再嘗試語意不變；不因替代動作重新發額度。
6. 保留完整 3 秒、全車身／砲塔／砲管形狀、既有查詢／時間限制及 Controller 實際物理防護。不改瞄準射擊、砲塔俯仰、作戰距離、導航半徑、建築或素材。

## 固定驗收

- R1：兩個真實姿態原命令 gun/#14 阻擋可重現；新入口得到安全非零命令。
- R2：以真 Controller 逐幀重評估執行，倒車案例 120 幀內至少 0.2 m 位移，轉向案例至少 3 度姿態進展；不得直接改 transform 冒充運動。另有 Navigation recovery 接線實跑。
- R3：原 0/0 不被替換；空曠安全命令保持；全阻擋仍有限兩次後停車，取消生命週期沿用原測試。
- R4：原基線地圖的 movement、navigation、recovery、predictive、contact 測試不改弱且通過；trace v2 仍可記錄候選。
- R5：交付街區場景可載入，使用者 scene／tres／素材不改。提供 F6 試玩與 F4 問題標記。

允許 production 修改只有 predictor 和 navigation；新測試、文件可新增。可信本機 Godot／既有資產、平面街區；不保證完整事件確定性回放、任意地形或所有街區必能脫困。跨幀鎖方向、砲塔接管與新全域尋路均延後。

## 複審與執行
