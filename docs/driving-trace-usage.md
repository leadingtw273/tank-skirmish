# 訓練場駕駛紀錄

在 Windows Godot 開啟 `training_ground_playtest.tscn`，按 F6 執行。每次執行會自動新增一組本機 JSONL 分段，無須錄影。請先停止舊遊戲再重開，讓新腳本生效。

- 問題出現時，將焦點放在遊戲視窗，按 **F4** 標記事件並立即 flush；接著繼續幾秒再停止。不要加 Alt 等修飾鍵。
- F9 是 Godot 內嵌遊戲的暫停／繼續鍵，已不再作為診斷標記；舊紀錄中的 F9 仍保留。
- 預設資料夾：`%APPDATA%\Godot\app_userdata\Tank Skirmish\driving_traces`。
- schema v2：每物理幀保存玩家／敵車姿態、速度與實際套用的操作（frame）；每 0.1 秒另存完整狀態與相對位置（sample）。AI 提交／Controller 套用／Recorder 觀測 frame 分開標示。
- 每次換車保存實際車型場景識別、物理參數、geometry hash 與形狀→車身／砲塔／砲管對照（actor_change.descriptor）；角度明示局部／世界、弧度及度數，砲口姿態附有效旗標。
- 每次新的預測 request 保存實際評估的候選、分數（有計算才填）、拒絕原因與第一個阻擋形狀／時間點（prediction）。intersect_shape 提供物件身分時才解析路徑；cast_motion 僅有安全比例時明示物件未知，不假造碰撞來源。查詢額度耗盡與幾何命中分開記錄。
- 碰撞開始／結束、路線及 AI 狀態轉換獨立記錄；各筆含時間、物理 frame、順序及物件身分。碰撞包含物件路徑、接觸點、法線與資料 age。
- 紀錄僅存本機、不上傳。每段預設 16 MiB，滿段後接續新段，不再因正常滿額停止。每段包含 session 身分、來源雜湊與當下狀態 checkpoint；分析時依同 session 的 segment 順序讀取。
- 循環保留本次遊戲最近 8 段；F4 額外保護最新標記所在段與前一段。只回收本次遊戲自行建立且不在保留集合的段，不刪以前遊戲的紀錄。重按 F4 會更新保護對象，因此不是永久封存每一次 F4。
- 正常輪替後本次遊戲至多 10 段／160 MiB。建立新段時暫多一個 pending 段；I/O／清理失敗會警告停止，含該 pending 最多 11 段／176 MiB。此限制不包含以往遊戲累積的檔案。
- F4 只有在標記確實寫入並 flush 成功後，才會印出 `DRIVING_TRACE marker=... file=...`。若發生 I/O 錯誤或單筆資料大到無法容納，請留意警告；不會假報標記成功。
- 平時每秒 flush；正常退出會 flush，強制中止可能遺失最後約一秒。這是診斷狀態重建，不是自動或可確定性重播；標記前後若有暫停，無 sample 的時間不可當成 AI 停滯。
- 僅 debug 圖形模式自動啟用，headless 預設關閉。此功能不修改導航、瞄準或脫困決策。

重現後告知「已重現」與大致情境，即可依最新 session／F4 marker 追查，不必貼上整份 log。
