# 敵方坦克移動（LEA-175）

本功能在既有訓練場實作，採單人、四車型互動驗收。不改玩家坦克物理、武器射程與瞄準機械限制。需求與初值已核可；工程測試與人類試玩狀態以工單紀錄為準。

## 行為

- 優先序：實際可見敵人 > 有效受擊查看 > 最後目擊位置。
- 看得見時追近：各車型獨立設定 `ai_stop_distance = 40`、`ai_resume_distance = 55`（公尺）。既有追近要到停止距離；已停車要超過恢復距離才重新前進。首次看見位於帶內則停車朝敵。
- 距離一律是雙方穩定車身中心的水平直線距離，不是砲口距離或繞障路徑長度。
- 停車後車頭朝敵，完成容差5度；太近不後退。此容差不放寬射擊條件。
- 行進時路徑轉向優先；砲塔／砲管仍可瞄準。固定砲塔不得為瞄準而偏離路線，真正符合原可見／機械／射線首撞與冷卻條件才射擊。
- 失視時前往最後目擊的穩定車身中心世界位置，不追讀隱藏玩家座標，且不開火。
- 搜索抵達原始位置3公尺內就待命，不巡邏。重新看見立即替換舊搜索；有效受擊停止並取消舊搜索，查看後未見目標就待命、不恢復舊路線。
- 基本繞障：部分路線走到末端停車；完全無路原地停車；途中卡住可有限次倒車恢復。路線末端不冒充抵達目擊點。
- 有行進／轉向需求但3秒內位移不足0.5公尺且朝向進展不足3度判卡住，正常有進展的原地轉向、減速與待命不算。兩次恢復後仍受阻則停車；同一不動目標不每幀重試，目標移動3公尺或新目標／重新可見才開始新嘗試。
- 可見且距離合適但射線受阻時，停車朝敵，不自行尋找射擊位置。

## 控制責任

`TankVision` 保留可見性與穩定中心查詢；`TankCombatAI` 保存記憶與交戰啟停狀態，並且是唯一車身指令出口；`TankNavigation` 只提供原生路徑跟隨需求，委託 `TankRecovery` 處理有限受阻恢復；`TankController` 保留真實物理、碰撞與砲塔機械約束。

AI 正常物理更新依序感知、決策、更新砲塔／砲管瞄準、取得導航需求、統一提交車身指令、最後檢查射擊資格。Controller 檢查實際姿態的旋轉碰撞並處理實體移動；瞄準輔助不自行把前進歸零。恢復中維持導航車身指令，不被朝敵轉向覆寫；耗盡恢復次數的 stuck 送零移動／零轉向。換車、死亡、停用及目標替換都清理舊路線與倒車狀態。

## 導航界線

使用 Godot 原生導航，地圖是訓練場固定地面與靜態建築；導航不直接寫 `velocity`，也不建立另一套駕駛物理。動態群體避讓與破壞後重烘焙不在本版。
四車共用朝前通行半徑3.6427174公尺：車頭 local -X、砲塔／砲管 yaw/pitch 為0時，量測每一碰撞頂點相對穩定中心的側向 local Z 最大絕對偏移；四車最大值2.6427174公尺加每側1公尺餘裕。包含砲管碰撞，但不再用完整旋轉包絡。這是路徑可通行近似，不保證任意砲塔姿態／長車轉彎皆可通過；安全由既有Controller碰撞與有限恢復保底。
先等導航地圖同步，再區分路線有效、部分末端及完全無路。原始目擊位置與投影後路線終點分開保存。

### 有限次倒車恢復

每個有效目標最多2次：先停穩至0.1m/s以下，低速直線倒車（上限1.5m/s），最多2公尺或2秒，距離含煞停預留；再停穩，依接觸資訊執行下述卡角調整，或在無可靠資訊時直接重新設定同一個原生代理的目標。沒有另外的直通捷徑或中繼點搜尋，也不強制傳送、縮小碰撞體或關閉後方碰撞。

卡角補強：觸發受阻時保存最近的水平碰撞接觸快照。側牆取外法線；正面牆角依接觸點位於哪側履帶決定遠離側。倒退停穩後，朝該側轉約30度（最多3秒）；角速度降到0.02rad/s以下後，以不超過1.5m/s短前進，最多2m或2.5秒，保留煞車距離。前移結束並停穩後才送出一次replan，避免只轉好就被原路線拉回牆角。若轉向被另一障礙擋住，逾時煞停並結束本次嘗試；Controller的實際旋轉／移動碰撞仍有效。沒有可靠側向接觸資料時，不猜方向，沿用直退後重查路徑。所有新增階段都受原兩次預算與目標／生命週期取消約束，不另建路徑搜尋。

後方堵住時不保證能退開；時間到仍煞停、重新嘗試導航，若兩次後持續無進展則 stuck。目標不變時保持停車，不無限反覆倒車。正常交戰距離過近不主動退後。

## 有限驗收清單

| 案例 | 可觀察結果 |
|---|---|
| A1 追近 | 四車80公尺追近到40±1公尺並停車朝敵，轉正<=5度。 |
| A2 雙門檻 | 首見47／55公尺不前進，56公尺追近；既有追近在47公尺不能提前待命。 |
| A3 過近 | 不倒退，持續朝敵。 |
| A4 射擊 | 固定／旋轉砲塔行進和轉正時可依原條件開火；隱藏或射線受阻零射擊。 |
| A5 隱藏搜索 | 隱藏玩家改位置不更新世界搜索點。 |
| A6 搜索完成 | 可走淨空區原目擊點3公尺內抵達後待命至少5秒。 |
| A7 優先中斷 | 受擊取消舊搜索；重新可見立即重定目標，可見優先。 |
| A8 建築繞障 | 四車真物理通過訓練場原建築繞行路線，不穿牆。 |
| A9 不可達 | 過窄通道不直穿；部分末端與完全無路分開，末端不能冒充抵達。途中卡住有限倒車，耗盡後停止；正常有進展的原地轉向不算卡住。 |
| A10 控制仲裁 | 行進路徑優先，停車朝敵；導航不寫車身控制，AI統一提交。 |
| A11 生命週期 | 停用、死亡、換受控車、清除／替換目標均清舊命令與搜索。 |
| A12 回歸 | 索敵、碰撞、射擊與玩家操控保持；僅更換被明確取代的靜止斷言。 |

## 實作與驗證順序

1. `scripts/bake_training_ground_navigation.gd` 從四車正式碰撞資產量測朝前側向範圍，烘焙原生靜態導航；不搬動建築或縮小其碰撞。
2. `TankNavigation` 提供純需求，`TankCombatAI` 整合追近、轉正與搜索；車型場景只新增距離參數，不變更物理或射擊常數。
3. `enemy_navigation_smoke.gd` 驗地圖與四車真繞障／部分末端；`enemy_navmesh_gap_smoke.gd` 驗窄口；`enemy_recovery_smoke.gd` 驗有限恢復；`enemy_movement_smoke.gd` 與舊 smoke 保留追近、搜索、記憶和射擊回歸。
4. `bash scripts/ci.sh` 序列跑完整回歸，獨立複審後交 Windows 試玩；人類驗收前不合併或結案。

## 不包含

正常交戰主動後退、巡邏、戰術選位、掩體策略、部位傷害與裝甲、動態破壞導航、多車編隊、多人網路、通用AI框架。倒車只用於受阻恢復。車頭朝敵只為未來正面裝甲提供行為基礎。

## 親測入口

### 編輯器更新導航

工具列與 `scripts/bake_training_ground_navigation.gd` 共用 `training_ground_navigation.tres` 的全部烘焙設定。來源模式為 Groups With Children，群組為 `training_navigation_source`：`Main/World/Ground` 與 `SightBlockers` 是來源；坦克、靶子與其他訓練道具不加入。搬動或新增在 `SightBlockers` 下的建築，會被兩個入口同樣解析；若新增獨立地板／建築根節點，需將該根加入同一群組。

1. 開啟訓練場，選取 `NavigationRegion3D`。
2. 按上方「烘焙 NavigationMesh」，等待完成並確認淡藍色可通行區域出現，再儲存場景／資源。
3. 按F6試玩。若誤按「清空」，再次烘焙即可重建；清空不是隱藏顯示。

目前 Agent Radius 約3.643公尺，其他烘焙尺寸與原版相同。腳本不暗中重設 Inspector 的烘焙參數；它額外量測四車朝前側向尺寸來驗證半徑下限，若更換車體幾何導致半徑不足會停止並告知，不覆寫導航資料。單純移動建築可直接使用工具列；變更坦克尺寸後，應先重新量測核對半徑。

在本次工作樹開啟 `src/world/training_ground/training_ground_playtest.tscn`，F6執行；沿用粉色敵方換車靶切換四車。拉遠觀察追近、靠近觀察停車朝敵、利用建築遮擋觀察最後目擊搜索；不要用仍指向舊工作樹的編輯器驗收。
