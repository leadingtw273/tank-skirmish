## Context 與四問覆核

- 目標使用者：Windows PC 單人坦克遊戲玩家，目前由 leadi 在 Godot 親測。
- 類似系統：沿用既有斜俯視街區坦克遭遇戰，不新增遊戲類型或複製外部內容。
- Identity：產品優先的 Tank Skirmish；不是通用感測器／物理引擎框架。
- 動機：讓掩體邊緣的碰撞、被發現與被射擊行為符合可見部位，並讓紅色視界能表達發現範圍。
- 覆核結果：產品定位不變；範圍由單純預覽擴為實際戰鬥與部位碰撞，已由使用者明確要求「一次做」。

## ADR：共享部位幾何與分開的發現／射擊判定

### 背景

現在的淡紅色地面預覽只畫近圈與遠扇形聯集，不裁切遮擋。AI 的視線與瞄準以玩家根 CollisionShape3D 中心為單一目標。四車使用固定整車 BoxShape3D，不能表達轉動後伸出盒外的炮管；只改可見性會造成看見、瞄準與砲彈命中不一致。

### 決策

1. **四車部位碰撞**：車體、存在的砲塔、左右履帶與炮管使用貼合各自模型輪廓的碰撞幾何，隨車體姿態、砲塔水平轉向及炮管俯仰更新。Tank1 沒有獨立砲塔模型，不虛構一個可被命中的砲塔；Tank4 固定上車體維持既有固定語意。
   - **履帶例外（2026-09-09 使用者核可）**：保留履帶視覺動畫，碰撞採整圈固定平滑外殼，不追蹤單片節片與縫隙。有限檢查以四動畫相位的原始幾何聯集凸外殼為準；不放寬其他部位精度，不新增執行期 skin bake。
   - **炮口例外（同日使用者追加「炮口也一樣」）**：保留可見炮口，物理碰撞可封閉炮口內孔，不要求物體穿入炮管；只豁免內孔，不豁免炮管外壁／階梯／頸部的既有輪廓精度。
   - **內部接合空洞例外（同日使用者核可直接填滿）**：被其他零件遮住的車身／砲塔接合空洞可封實；可見外側凹槽與主要外輪廓仍維持原 0.05m 目標，不把整個部位凸包當作新的標準答案。
   - **裝飾例外（同日使用者追加「車身上的一些裝飾細節不需要有碰撞」）**：天線、小把手、螺栓等非主要結構裝飾保留顯示，但不要求獨立碰撞，也不選作可命中的表面取樣點。不能只因構件小就刪除；主要車身、砲塔、炮管與左右履帶仍保留。驗證參考取自原模型的主要結構加核可封口；被排除裝飾的原始差異另列，不以碰撞資源反推參考。
2. **實體阻擋**：精修碰撞不只用於射擊。車體移動／轉向、砲塔轉動及炮管俯仰遇建築或其他實體障礙時，只阻止會繼續擠入的動作；可反向轉動、倒退或移動脫離。不自動推開／彈開坦克，不新增避障、繞行或追逐。
3. **視覺與血量邊界**：不把煙火、砲口特效、純視覺後座或履帶塵煙當成新命中部位。沿用整車 Health、傷害、無敵與損傷視覺，不新增部位血量、裝甲或斷履帶／斷炮管玩法。
4. **局部發現**：以部位表面多點取樣代替單中心鎖敵。任一有效取樣點位於既有近圈／遠扇形範圍內且從敵方觀察位置可見，即可發現；不因車體中心被擋而排除。部位包含車體、砲塔、履帶與炮管，只有炮管露出亦適用。觀察位置沿用砲塔位置，距離與遠扇形以既有水平範圍定義判斷各取樣點。
5. **取樣精度**：使用者接受部位表面多點檢查可能漏掉極細縫／微小露出；不宣稱逐像素、精確三角形可見性或任何細小露出都有保證。碰撞形狀及取樣點必須來自模型部位，不能以遠離模型表面的 AABB 外角製造假可見目標。
6. **中心優先與替代瞄準**：穩定的車身中心可見，且炮口有可命中路徑時優先瞄準中心；否則使用其他可見且炮口路徑可通的部位點。若有可見點但全部炮口路徑被擋，維持鎖定／瞄準、不開火；不改為對掩體盲射。
7. **真實開火守門**：仍需炮管實際對準選定部位，且當前實際炮口方向通過既有無遮擋開火檢查。保留射速、擴散與 ShotEvent→Projectile→ImpactEvent→DamageReceiver；「可射」不代表每發含擴散的砲彈保證命中。
8. **遮擋物**：沿用現行 Vision 的碰撞範圍：建築、其他坦克、殘骸與地形；實際觀察排除觀察者本身。不能因部位碰撞改動讓本人或同一坦克的其他部位變成外部遮擋者。
9. **紅色視界語意**：表示觀察者砲塔高度的水平可見範圍，近圈與遠扇聯集皆依遮擋截斷；保留淡紅色、alpha 0.15 與交疊不加深。不再表示玩家必定可被發現，也不表示炮口可射。
10. **水平遮擋**：從觀察者 view_origin 在同一高度向外查詢；同高度建築、其他坦克（含玩家）、殘骸與地形阻擋，低於視線的物體可越過。只排除觀察者，不再虛擬搬移玩家／依玩家姿態逐格取樣；輪廓投影至地面顯示，不新增導航或出生點保證。
11. **預覽與 AI 分工**：預覽共用觀察者的近／遠半徑、砲塔方向、FOV 與碰撞遮罩，但採水平輪廓；AI 保留精確部位範圍／LOS 與真實射擊守門。紅色只顯示，不控制 AI 或開火；矮車可能藏在低物後而位置仍為紅色，這是已核可的提示精度取捨。

### 被否決的替代方案

- 保留完整理論紅圈／紅扇：不能表達物件遮擋。
- 僅檢查／射擊車體中心：使用者明確要求局部露出也可被發現及射擊。
- 局部可見但仍只用舊整車盒判命中：炮管等伸出部位會發生實彈穿過，不符本次要求。
- 為避免卡牆而強制讓炮管／砲塔不參與實體阻擋：使用者已核可卡住建築，並要求能反方向脫離。
- 只優化預覽、碰撞留後續：使用者裁決一次做。
- 逐像素、無限精度露出判定：使用者接受表面多點取樣及其微小露出漏判限制。
- 只有中心高度的預覽、或把紅色當射擊範圍：使用者選擇目前玩家車型與姿態的可發現範圍。

### 影響與相容邊界

直接涉及 Tank 的部位碰撞／姿態更新、Vision 可見性、CombatAI 選點／開火及 VisionPreview。既有車身中心資料仍須穩定，不能拿暫時選定的瞄準點覆寫它，避免破壞「車身中心→受擊點」的查看方向。玩家／敵人換車與玩家重生都需使用新車自身部位資料，不殘留舊 RID／節點／候選點；殘骸清除改依可編輯固定區域：任何部位碰撞與區域重疊即清除，含先進區後死亡；區外殘骸不因重生被清除，舊車提早消失仍須正常重生。

## 固定驗收矩陣

| 編號 | 案例與判定 |
|---|---|
| C1 | 四車存在部位的碰撞與模型在正常車體姿態、砲塔轉向、炮管俯仰下對齊；無虛構部位／VFX 碰撞。以原有射擊管線命中車體、履帶、砲塔（實際存在者）、炮管均交給同車 Health。 |
| C2 | 現有訓練場建築前：車體平移／偏航、砲塔水平轉向、炮管俯仰均不能把對應碰撞部位繼續插入建築；反方向／倒退可脫離。不能只驗候選終點，而漏掉一次轉動跨過障礙物。 |
| C3 | 無障礙平地保持現有前進、倒車、原地轉向、砲塔瞄準及固定砲塔車身輔助功能；接地不應讓全部轉動被鎖住；不因碰撞新增自動推開／彈開另一台坦克。 |
| V1 | 車體邊緣、砲塔、履帶、炮管各自單獨露出的有效取樣案例；中心被遮擋時，在近圈與遠扇形內均可發現。四車依實際存在的部位參數化覆蓋；Tank1 不造假砲塔案例。 |
| V2 | 全部取樣點被遮擋、或全部點位於近圈／遠扇形聯集之外時，不發現；建築、其他車與殘骸均可遮擋；本人不自擋。 |
| A1 | 中心可見且炮口路徑可通時選中心；中心被擋或炮口到中心被擋、但另一露出部位可射時選該部位；選點具有實際可命中的碰撞表面。 |
| A2 | 可發現但所有可見部位的炮口路徑被擋時，持續瞄準、不開火；遮擋解除後依現有對準與射速規則開火。至少一例以真實 Projectile 命中替代部位並扣血，不只直接呼叫傷害或 AI API。 |
| P1 | 以連續三角輪廓顯示近圈／遠扇聯集、淡紅透明度並跟隨砲塔；同高度障礙在兩種範圍皆截斷，低物可越過，不再畫方格遮罩。必須驗證真渲染，不能只看 uniform 或 headless。詳 S1、S2、S4。 |
| P2 | 固定方向端點與獨立水平 ray oracle 對照，驗低／高牆、真殘骸、自身排除、其他車保留、轉砲塔／移動遮擋後下一完整 physics 更新及停用／失效行為。AI 的四車／部位回歸另保留於 V1/V2/A1/A2。詳 S1–S3。 |
| R1 | 保留既有近圈受擊查看、中心→命中點方向、換車、敵方 AI 目標／射擊來源重綁、3 秒中央重生及 2 秒無敵閃爍。清骸改依固定區域 Z1–Z5：區內即清且僅編輯器顯示，區外保留；死亡車提前被清除後仍正常重生。只更新被新規則取代的清骸／死亡車保留斷言，不削弱其餘 smoke。 |

取樣密度、碰撞近似容差、旋轉檢查步長與預覽更新預算由實作計畫明列並實測；不以「有限取樣」為由跳過上表正常側露、炮管露出與建築碰撞案例。計畫若無法在現有場景維持可操作性，需回報具體量測與選項，不默默降低部位範圍或更換紅色語意。

## Threat model／非目標

本次為可信本機手調的現有四種坦克與訓練場、既有物理更新頻率及可達操控角速度。排除任意超高速瞬移、無限薄牆的數學 CCD 保證、惡意模型／腳本、跨平台任意引擎版本、多人網路、導航、通用物理插件、戰爭迷霧、部位損壞、存檔與部署。這些排除不豁免正常控制速度下炮管不能掃穿現有建築的要求。

## 澄清清單

1. 近圈與遠扇形都裁切，後方不上色？**是**。
2. 遮擋物沿用 AI 範圍，包含建築／其他車／殘骸／地形，排除自己？**是**。
3. 鎖敵只看中心？**否**，任一部位露出可發現，中心露出優先射中心。
4. 砲塔／履帶／炮管單獨露出也算？**全部算**。
5. 看見但炮口被擋時保持瞄準不射；其他部位可射就切換？**可以**。
6. 紅色代表發現還是射擊？**發現玩家**。
7. 模型貼合碰撞造成轉動卡建築可接受？**核可**。
8. 碰撞精修留後續？**一次做**。
9. 只擋加深碰撞、反向可退出、不推彈坦克？**可以**。
10. 接受部位表面多點精度、極微小露出可能漏判？**可以**。
11. 預覽依目前玩家車型與姿態，表示放在該位置時任一部位可見？**可以**。

## 已知風險與規劃閘門

- Godot 內建線性 motion query 不等於旋轉掃掠；實作方法須先通過有限的旋轉／接地／退出驗證，不能以終點不重疊宣稱途中不穿牆。
- 多點取樣的精度限制已核可；預覽場域查詢成本尚需量測，不能把逐格大量同步射線帶來的停頓當正常完成。
- 現有 GLB 的部位結構不同，Tank1 無獨立砲塔、Tank4 上車體固定；須沿用現有車型能力，不為統一資料而改車型玩法。
- 程式／測試實作只在規格審查與計畫裁決後開始；預備性驗證限隔離暫存測試，不改使用者現有場景。
